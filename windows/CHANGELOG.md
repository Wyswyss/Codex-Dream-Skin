# Windows Changelog

## Unreleased

### 安全

- Windows 注入传输改为 Chromium 继承式 `--remote-debugging-pipe`：Node 守护进程直接启动官方 Store `ChatGPT.exe`，通过子进程的匿名管道收发 CDP，不创建 TCP 监听器，也不提供端口模式回退。
- Node 以精确可执行路径、`shell: false`、官方可执行文件所在工作目录和受控子进程生命周期启动 Codex；管道断开会结束本次主题化的 Codex，启动或注入验证失败则显式关闭管道并等待 / 结束精确子进程。无法证明清理完成时保留恢复状态和证据。
- Appx 发现要求 `SignatureKind=Store` 且不是 development mode；同名开发包或侧载包不会被当作官方 Codex 启动或关闭。
- 新状态记录绑定随机会话 ID、Node / Codex PID、精确路径、进程启动时间、参数和 Store 包身份。Verify 还要求原子本地状态的心跳足够新、renderer 结果通过；身份无法完整证明时不会结束目标进程。
- 状态心跳用于抵御过期文件、PID 复用和误操作，不是针对同一用户恶意进程的密码学认证。匿名管道缩小了攻击面，但无法防御已经能复制句柄或注入进程的本机恶意软件。
- injector 日志与状态文件不记录窗口标题、页面路由、页面文本或用户内容，只保留临时 target ID、结构标记和布局结果。
- Windows 内置 payload 只使用本地 CSS、renderer 与内嵌图片 data URL；三项已审阅资源由固定 SHA-256 约束。远程资源 / 网络 token 扫描只是附加审查提示，不作为脚本沙箱。
- 快捷方式不会静默携带 `-RestartExisting`；需要重启现有 Codex 时先向用户确认。
- install、start、restore 和 verify 对 `%LOCALAPPDATA%\CodexDreamSkin` 中的锁文件持有跨登录会话的独占句柄，避免同一账户在 console / RDP 双击或并发命令竞争配置、状态和进程。

### 修复

- 渲染层现在只在检测到完整 Codex 主界面壳层时启用皮肤；宠物等透明辅助窗口会主动清理主题背景与装饰节点，避免出现遮挡宠物的矩形背景框。
- 安装与 `-RestoreBaseTheme` 严格按 UTF-8 读取，保留原换行风格，并以无 BOM、同目录原子替换方式写回 `config.toml`，避免中文项目名称乱码或导致 Codex 无法启动。
- 遇到带 BOM / 无 BOM 的 UTF-16、NUL 字符、无效 UTF-8 或写入期间被其他程序改动的配置时停止修改，不再静默转码或覆盖较新的内容。
- 安装会在当前注册包或 state 记录的旧 Codex 仍运行时明确提示先关闭；配置临时文件写完后会在原子替换前再次核对原始字节，进一步缩小并发覆盖窗口。
- 条件配置替换在最终字节比较到替换期间持有拒绝普通写入者的文件句柄；不遵守 Windows 共享模式、已取得特殊句柄或直接修改用户文件的外部进程仍不属于可提供真正 CAS 的边界。
- 快捷方式先写入私有暂存目录，配置提交后才按原始字节条件替换目标；任一快捷方式失败会回滚本次已写入的快捷方式和配置，无法安全回滚时明确报告不完整状态。
- 配置恢复只修改 `[desktop]` 内的外观键，不再误碰其他 section 的同名配置；新增 `-RecoverConfigBackup` 用于显式恢复安装前原始文件，并先保存当前文件。
- 完成配置恢复后会归档本轮安装前备份，使下一次安装重新保存当时的配置，避免重复安装使用过期主题值。
- 新 schema 的清理只停止与记录的 Node 路径、injector 脚本、会话 ID、状态路径、Codex 子进程和启动时间全部匹配的守护进程；旧 state 无法安全验证时会原样保留并停止操作，而不是猜测性结束进程。
- 启动验证失败会停止守护进程、通过管道断开关闭本次新开的 Codex，并在确认二者退出后清理新证据、恢复无调试参数的普通启动；若无法确认则保留 schema 4 恢复状态，不删除诊断线索或猜测性重开。
- Restore 先验证并停止本次会话的守护进程，等待主题化 Codex 随管道关闭退出，再写配置并正常重开；失败时保留可诊断状态，不再静默报告假成功。
- Store 更新后的记录路径，只有在 Appx full name、family name、安装目录和可执行文件仍能与系统注册包匹配时才允许自动控制；无法证明归属时要求手动关闭。
- Store 更新时重新发现当前注册版本。若已有版本与新包并存，会安全停止并提示人工处理，不会并行启动第二个无法验证的 Codex。
- 支持带注释或引号的 `[desktop]` 表头与目标键；遇到转义同义键、多行字符串 / 数组、dotted key、重复目标键或 `[desktop.*]` 子表时会在写入前明确停止，避免把合法但无法安全行编辑的 TOML 改坏。
- Restore 不要求 PATH 中仍能找到 Node；清理使用安装时保存且经过精确身份验证的 Node 路径，Node 已升级或卸载也不影响安全恢复。

### 改进

- injector 作为 Codex 的有状态父进程持续持有私有管道，等待首轮注入验证成功，并只在重新探测仍是完整 `app://` Codex 壳层后重应用现有 CSS、装饰 DOM 和图片资源。离开允许协议的 target 会立即失效并 detach。
- 目标异常时使用有上限的指数退避和限频日志；管道关闭或协议错误会停止会话，首次成功后连续 30 秒没有新鲜健康目标也会关闭会话，不会寻找网络端点继续连接。
- 明确要求 Node.js 22 或更新版本，并记录真实 `process.execPath` 与版本，兼容 PATH 中的启动转发程序。
- Verify 改为读取本次会话绑定的新鲜状态及 renderer 验证结果。安全模式不建立第二条 CDP 连接，因此 `-ScreenshotPath` 明确返回不支持；视觉验收改为实机人工步骤。
- 带空格或结尾反斜杠的测试 profile、握手和状态路径按 Windows 命令行规则引用。

### 测试

- 增加匿名管道传输回归测试，覆盖 NUL 分帧、碎片 / 合并消息、flattened session 路由、命令超时、非法 JSON / UTF-8、超大帧、断开和待处理请求拒绝。
- 增加静态安全检查，确保 Windows 新启动与 injector 路径不包含 TCP 调试参数、网络探测或兼容回退。
- 增加渲染层辅助窗口回归测试，覆盖主窗口正常注入、透明辅助窗口清理残余样式，以及辅助目标随后成为完整主界面时可重新启用皮肤。
- 增加中文项目路径、CRLF / LF、UTF-16 与歧义 TOML 拒绝、并发写检测、section 隔离、精确恢复、Appx / state 身份、严格状态解析、每目标验证新鲜度、payload 哈希、导航离域、PowerShell AST 解析和会话新鲜度回归检查。
- 自动化检查不能替代真实 Store 包、Windows 句柄继承、当前 Codex DOM 和最终视觉验证；发布前仍要求完成 `references/qa-inventory.md` 的 Windows 实机签核。
